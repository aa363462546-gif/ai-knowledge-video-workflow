# AI 视觉设计与动态制作

根据当前请求完成静态设计、动画或成片，不自动扩大任务。正式口播制作以项目 `正式制作流程.md` 的当前执行部分为入口；无需每次读取通用视频 Skill 或研究渲染底层。本 Skill 支持完整创作，不固定页模板，不压缩精细 SVG 或自由动画。

正式口播创作在设计、编码前必须读取 [视觉资产质量](references/visual-assets.md) 和 [动态导演、场景空间与时间](references/motion-and-time.md)，由原有创作 Agent 直接落实。按正式流程复制本 Skill 时包含 `references/`，各片段读取任务内同一份冻结副本；不增加审核、评分或制作步骤。

## 1. 统一视觉语言，按内容自主设计

读取 [Design System](../../design-system-v1/DESIGN-SYSTEM.md) 的使用边界、字体、颜色和阅读层级（§1–4）。正式视频封装已加载 `tokens.css` 和本地字体，场景直接使用其变量，不重复写 `<link>` 或 `@font-face`；独立静态页面才自行引用 [tokens.css](../../design-system-v1/tokens.css)。边界、图表、关系图、质感细节按需读 §6–10；[预览](../../design-system-v1/index.html) 只说明视觉语言，不是页面模板。根据文件位置解析相对路径，无需另建字体或色板。

Design System 统一视觉语言；内容、构图、HTML/CSS/SVG 和动作由当前任务决定。可以创作新图形、组件与动画，同一作品保持对象身份、信息层级和语义颜色一致。

## 2. 从观看任务选择表达

先判断观众此刻要认出什么、比较什么或理解什么变化，以及原材料提供了哪些对象、顺序、关系和依据。按解释收益选择物体绘图、动态图表、文字、关系图或组合，不按关键词套组件，不补造事实或因果。

少量顺序步骤可用文字列表或编号胶囊；需要追踪依赖、分支时再用流程图。简单内容直接选择清楚的表达，有真实取舍时再比较候选。现成组件合适就复用，不合适自主绘制。

### 自动选择 2D、2.5D 或 3D

连贯理解完整口播和 SRT，再判断观众此刻需要看见的对象与关系。用户明确指定表达方式时优先遵从；未指定时，2D、2.5D、3D 均为正常候选，不设默认维度或固定使用比例，同一片段可自由混合。综合判断文字精确阅读、数据比较和逻辑解释的需要，以及主体的体积、纵深、空间关系、机械结构、运动与镜头绕行，选择更直观、自然的表达：

- **2D**：文档、文字、图表、数字、数据比较和逻辑说明通常适合 HTML/CSS/SVG + GSAP；相关场景也可采用空间表达，必要文字保持清晰可读。
- **2.5D**：具象物体与空间关系可主动考虑层次、投影、透视或等距图解。简单 SVG 透视也能形成有效的立体表达，可沿用 HTML/CSS/SVG + GSAP，不必为实现 2.5D 加载 Three.js。
- **3D**：需要真实深度、三维结构、空间运动、遮挡、旋转拆解或镜头绕行来解释内容时，直接调用已接入的 Three.js，按当前内容创建场景。

选择依据是当前完整讲解含义与视觉表达效果，技术复杂度本身不是目标；同时考虑相邻场景的视觉主体、焦点与镜头交接，沿用现有动态与空间规则。不按程序关键词切换，不需要用户逐幕指定，也不固定模板。沿用现有全文背景或交付 README 简记选择理由，不增加规划字段、评分、门禁或 Agent 系统。选择三维后，按当前讲解重新创建真实几何体、材质、灯光、摄像机与动作；不能拿历史芯片或预渲染视频充当新场景，不为三维简化其余场景。

选择 3D 时读取 [可选 Three.js 接口](references/optional-three.md)。三种表达共用现有时间轴、字幕、音轨和合成，颜色从原 Design System 变量取值，文字仍由原 HTML/SVG 承担；不改画风、不新增播放器或导出链。

## 3. 让主体与空间共同成立

先按视觉主体的重要性和当前观看任务，自主选择整屏聚焦、合理分栏／分区或局部放大：

- 文档或物体本身是主角时，可以整屏聚焦，取消与主体或字幕重复的说明。
- 图形与文字都重要、需要同时阅读时，为双方分配充分的可读空间；分区和比例随内容决定，不预设固定分栏。
- 只解释某个局部时，优先推近该局部，整体可退场或仅保留必要的定位线索；保持对象身份不等于始终展示完整物体。

用最长必要文本、真实数据或关系组织可读状态。字号随信息角色和观看尺度决定；用共同边界、基线、组间距离区分关系，比较时便于对照，主次也可非对称。主体过小先调整组比例，拥挤先去重复、重组或分时展示；不得靠不断缩小字号、把说明挤入巨大主体剩余的窄栏来维持原构图。

必要名称、数字、单位、条件与关系标注清楚可读。主画面不逐字复述 SRT，不用灰色小字、重复标签或制作备注填留白。标题与图形按本场景的可用空间和运动范围分层，不强制统一标题条或卡片布局；必要时只裁切局部图区，不给全画面套统一裁切。尺度或选图困难时按需读 [设计判断方法](references/design-decisions.md)。

## 4. 状态、动作与定位分层

以下要求由现有创作 Agent 在编写 HTML/CSS/JavaScript 时直接落实，不另生成规划文件或增加工作流步骤：

- **先排完整状态，再写动画**：编写动画前，先确定每个关键可读状态的完整布局。空间占用包括主图形、标题、标签及完整文字、信息卡片、强调框及描边、连接线和其他同时可见元素，并按完整运动范围留出空间。所有需要同时阅读的内容必须有明确的位置关系，不能只考虑图形本体。
- **新内容出现，旧内容必须有去向**：每次引入新的主要结论或强调元素，必须决定已有元素继续保留、退出、替换、缩小并移开或重新布局；只有仍承担解释作用的内容才继续保留，不能默认全部累积。降低透明度不等于退出，也不能代替让出空间。
- **每个状态明确主次**：同一可读状态应有一个明确的主要结论，必要的辅助信息可以共存，但历史说明、警告框和强调元素不能始终保持同等级强调。连续因果关系优先采用“前一状态 → 内容交接 → 下一状态”，而不是不断叠加；这不限制卡片数量，也不限制合理的多元素构图、复杂动画与多层次叙事。
- **避免无意义遮挡**：标题、标签、警告卡、强调框、连接线和装饰元素不得遮挡仍需阅读的文字或关键关系，此约束同时适用于稳定画面与转场全过程。允许有明确叙事目的的覆盖、替换、遮罩和层叠；新内容接替成为主体时，旧内容应合理退出或让位，不以统一禁止重叠牺牲画面层次。
- **动画目标与实际元素一致**：JavaScript 选择器必须对应 HTML 中实际存在的元素，不能把仅有 `class` 的元素按不存在的 `id` 查找。编写动画时直接确保目标存在，预期入场、退出时点与状态交接一致，不新增独立检查脚本。

制作片段是渲染单位，同一片段可包含多个论点、可读状态和镜头；不按片段秒数或每条 SRT 决定换画面。

编写各状态和动画前，结合全文明确核心对象、哪些对象应贯穿多个论点，以及新旧信息是因果、从属、对比、流程延续还是话题转换。分清同一对象的状态变化、新实例出现和独立话题，不先按句子分配独立容器。

需要追踪同一对象或过程时，优先保留对象身份并改变状态；信息扩展或由依据进入结论时，先考虑从已有节点展开、聚合或重组已有对象来承接。只有原文确实支持的关系才在画面中建立联系；没有解释作用的旧内容按上面的去向规则处理，不强行保留。

相邻状态的衔接按观看任务选择：同一焦点补充信息可保持画面；需要重新对照或分组可改变布局；整体与局部可考虑推近、拉远，流程关系可沿链路推进；无直接关联或连续承接反而妨碍理解时可清晰直切。按解释需要组合，不固定对应，不要求所有视频使用运镜、卡片或一镜到底。

焦点交接先明确观众原来在看谁、接下来应看谁、哪些依据仍需可见，再安排旧内容退居次要位置和新内容接管注意力。分清语义时点、动作耗时和稳定阅读；重要文字与关系进入阅读时停止主要镜头，避免无关对象同时运动，必要的局部过程可以继续。沿用原 SRT 时点，不提前揭示关键结论，不为画面改写或变速原音频。

采用现有 GSAP 暂停时间轴与 `renderAtTime(seconds)`，使画面由片内时间确定。外层负责布局定位，内层负责 GSAP 运动，避免 SVG 原生 `translate` 被同对象 `x:0,y:0` 覆盖。具体导演、场景隔离与定位做法见上述必读的 [动态参考](references/motion-and-time.md)，不默认读取底层实现。

## 5. 交付与按需视觉评审

正式制作保留每段首次完整创作，源码明确完成即交给渲染；不做逐段 AI 审美、截图自查、视觉评分、评审 Agent 或自动主观返工。最终基础程序检查按正式流程执行，技术通过不代表审美或用户验收。发现可复现技术故障时仅定点修复、复核。

V2 的 `pack` 在源码包验证后自动复制三个交付文件到正式流程指定的统一绝对归档根目录，保留原工程和历史成片。使用现有分段表顶层 `title` 记录从完整口播提炼的简短中文主题，无需新增字段或文件，普通制作无需另执行归档命令；V1 标签和旧任务冻结适配保持原样，不会自动升级。

只有用户明确要求视觉评审时，才读取和执行 [视觉评审](references/visual-review.md)；它不构成默认制作门槛。
